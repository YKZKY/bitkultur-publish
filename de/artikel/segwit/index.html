SegWit einfach erklärt: Was das Bitcoin-Upgrade von 2017 veränderte

BitKultur · 6 Minuten Lesezeit · Veröffentlicht: 27 November 2026

SegWit ist ein 2017 aktiviertes Bitcoin-Protokoll-Upgrade. Der Name steht für „Segregated Witness“, also getrennte Witness-Daten. Die Änderung behob eine wichtige Form der Transaktions-ID-Malleabilität und veränderte die Messung der Blockkapazität.

Welches Problem sollte gelöst werden?

Bitcoin-Transaktionen enthalten Signaturen. Die Transaktions-ID, kurz TXID, ist ein Hash der Transaktionsdaten. Im älteren Format konnten bestimmte Änderungen an den Signaturdaten die TXID verändern, obwohl die beabsichtigte Zahlung gleich blieb. Das nennt man Transaktionsmalleabilität. Sie erschwerte Systeme, die von unbestätigten Transaktionen abhängen.

Was trennte SegWit?

Das Upgrade verlagerte Daten, die zur Prüfung einer Transaktion nötig sind, darunter Signaturen, in eine separate Witness-Struktur. Die herkömmliche TXID enthält diese Witness-Daten nicht; die neue wTXID schon. Dadurch wurde eine unbeabsichtigte Änderung der TXID stark eingeschränkt und der Aufbau von Off-Chain-Zahlungskanälen erleichtert.[1][2]

Was bedeutet Blockgewicht?

SegWit führte neben der früheren einfachen Byte-Grenze das Blockgewicht ein. BIP 141 definiert es als Basisgröße × 3 + Gesamtgröße; das Maximum beträgt 4 Millionen Weight Units. Witness-Daten zählen weniger, sodass ein Block je nach Transaktionsmix mehr Daten enthalten kann. Das bedeutet weder, dass jeder Block 4 MB groß ist, noch dass die Netzwerkkapazität unbegrenzt wurde.[1]

Die virtuelle Größe einer SegWit-Transaktion kann kleiner sein als ihre vollständige Byte-Größe. Dadurch kann die Gebühr geringer ausfallen, abhängig von der Nachfrage nach Blockplatz und den Wallet-Einstellungen.

Wie wurde das Upgrade aktiviert?

Die Aktivierung war 2016 und 2017 Gegenstand großer technischer und organisatorischer Debatten. BIP 141 sah zunächst eine festgelegte Schwelle für das Miner-Signal vor. BIP 91 schuf einen Koordinationsschritt mit niedrigerer Signalisierungsschwelle, während BIP 148 eine mögliche von Nutzern und Nodes aktivierte Soft Fork beschrieb. SegWit wurde schließlich im August 2017 aktiviert.[3][4]

Der Vorgang zeigte: Ein Bitcoin-Upgrade erfordert neben Software auch die Abstimmung verschiedener Ökosystem-Teilnehmer. Es wäre zu einfach, den Ausgang als Sieg einer einzigen Gruppe oder deren alleinige Aktivierung zu beschreiben.

Was bedeutet das heute für Nutzer?

SegWit wurde zu einem weit verbreiteten Transaktionsformat; die Unterstützung hängt jedoch von den verwendeten Wallets ab. Es kann die für Gebühren relevante Transaktionsgröße verringern und die Stabilität der TXID verbessern. Niedrige Gebühren oder schnelle Bestätigungen garantiert es nicht, denn die Nachfrage nach begrenztem Blockplatz bleibt entscheidend.

Einige Abläufe beim Aufbau von Lightning-Zahlungskanälen profitieren von stabileren TXIDs durch SegWit. Das Upgrade allein hat Lightning jedoch nicht geschaffen. Taproot war ein separates Upgrade, das 2021 aktiviert wurde.[5]

Kurz zusammengefasst

  • SegWit trennte Validierungsdaten von den Hauptdaten einer Transaktion.
  • Es verringerte die TXID-Malleabilität und führte das Blockgewicht ein.
  • Es kann Gebühren senken, beseitigt aber nicht den Wettbewerb um Blockplatz.
  • Die Aktivierung 2017 war sowohl eine technische Änderung als auch eine Koordinationsgeschichte des Ökosystems.
