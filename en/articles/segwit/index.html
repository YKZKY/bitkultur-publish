SegWit Explained: What Bitcoin’s 2017 Upgrade Changed

BitKultur · 6 min read · Published: 27 November 2026

SegWit was a Bitcoin protocol upgrade activated in 2017. Its name means “Segregated Witness.” The change addressed one important form of transaction ID malleability and changed how block capacity is measured.

What problem was it addressing?

Bitcoin transactions contain signatures. A transaction ID, or TXID, is a hash of transaction data. In the older format, certain changes to signature data could alter the TXID without changing the intended payment. This is called transaction malleability. It made systems that depended on unconfirmed transactions harder to design.

What did SegWit separate?

The upgrade moved data needed to validate a transaction, including signatures, into a separate witness structure. The traditional TXID does not include this witness data; the new wTXID does. This greatly reduced unintended TXID changes and made it easier to build systems based on off-chain payment channels.[1][2]

What is block weight?

SegWit introduced block weight alongside the earlier simple byte limit. BIP 141 defines it as base size × 3 + total size, with a maximum of 4 million weight units. Witness data counts less, so a block can carry more data depending on its transaction mix. This does not mean every block is 4 MB or that network capacity became unlimited.[1]

A SegWit transaction’s virtual size can be smaller than its full byte size. Its fee can therefore be lower, depending on demand for block space and wallet settings.

How was it activated?

Activation became the focus of major technical and governance debates in 2016–17. BIP 141 initially relied on miner signaling at a defined threshold. BIP 91 introduced a coordination step with a lower signaling threshold, while BIP 148 described a possible user and node activated soft fork. SegWit ultimately activated in August 2017.[3][4]

The episode showed that a Bitcoin upgrade involves coordination across the ecosystem as well as code. It is too simple to describe the outcome as one group winning or activating it alone.

What does it mean for users today?

SegWit became a widely used transaction format, though support depends on the sending and receiving wallets. It can reduce transaction size for fee purposes and improve TXID stability, but it does not guarantee low fees or fast confirmation. Demand for limited block space still matters.

Some Lightning Network channel processes benefit from SegWit’s more stable transaction IDs, but SegWit alone did not create Lightning. Taproot was a separate upgrade activated in 2021.[5]

In brief

  • SegWit separated validation data from the main transaction data.
  • It reduced TXID malleability and introduced block weight.
  • It can help lower fees but does not remove competition for block space.
  • Its 2017 activation was both a technical change and an ecosystem coordination story.
